# Support

## Where to ask

GitHub Issues is the only support channel — Discussions are not enabled.

| What you have             | Where it goes                                                                                         |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| Something is broken       | [Bug report](https://github.com/no42-org/blitsbom/issues/new?template=bug_report.yml)                 |
| You want a feature        | [Enhancement request](https://github.com/no42-org/blitsbom/issues/new?template=enhancement.yml)       |
| A question about using it | [Open an issue](https://github.com/no42-org/blitsbom/issues/new/choose) and pick the closest template |
| A security vulnerability  | **Not an issue** — see [SECURITY.md](./SECURITY.md)                                                   |

Before opening anything, please [search existing issues](https://github.com/no42-org/blitsbom/issues?q=is%3Aissue). Closed ones often contain the answer.

## What helps a report get fixed

The single most useful thing is **a sample SBOM that reproduces the problem**. Redact whatever you need to — a trimmed file with three components that still misbehaves is far more useful than a description of a 30 MB one that we cannot run.

Also worth including: your browser and version, whether you opened the page from `file://` or a web server, and what you expected to happen instead.

## Expectations

This is a small project maintained by volunteers in their own time. Issues are read, but there is no response-time guarantee and no commercial support offering. Well-scoped pull requests are the fastest route from "this bothers me" to "this is fixed" — see [CONTRIBUTING.md](./CONTRIBUTING.md).
